## 三、数据流详解

### 3.1 个股评分流程

```
用户输入股票代码 → 选择评分体系 → 点击评分
                                  │
                                  ▼
                    ┌───────────────────────┐
                    │ 获取近5年财务指标       │
                    │ calculate_yearly_     │
                    │ features(code, years) │
                    └───────────┬───────────┘
                                │
                    ┌───────────▼───────────┐
                    │ income 表 → 利润/营收   │
                    │ balance 表 → 资产/负债  │
                    │ cashflow 表 → 现金流   │
                    │ financial_indicator    │
                    │ 表 → 毛利率/周转率       │
                    │ 数据缺失 → 自动网络下载   │
                    └───────────┬───────────┘
                                │
                    ┌───────────▼───────────┐
                    │ 计算各项评分指标        │
                    │ (不同评分器逻辑不同)     │
                    └───────────┬───────────┘
                                │
                    ┌───────────▼───────────┐
                    │ 获取实时估值(PE/PB)     │
                    │ akshare.stock_value_em  │
                    │ → 网络请求              │
                    └───────────┬───────────┘
                                │
                    ┌───────────▼───────────┐
                    │ 计算总分 + 评级         │
                    │ 返回结果字典            │
                    └───────────┬───────────┘
                                │
                    ┌───────────▼───────────┐
                    │ GUI 显示结果            │
                    │ 文本区 + 表格 + 历史    │
                    └───────────────────────┘
```

### 3.2 全市场扫描流程

```
用户选择市场范围 + 评分体系 + TopN
                                  │
                                  ▼
                    ┌───────────────────────┐
                    │ 从 stock_basic 获取     │
                    │ 指定市场的股票列表       │
                    │ (约 500~5000 只)       │
                    └───────────┬───────────┘
                                │

                    │ 对每只股票依次评分       │

                    └───────────┬───────────┘
                                │
                                ▼
                    ┌───────────────────────┐
                    │ 按总分降序排序          │
                    │ 取前 TopN 名           │
                    └───────────┬───────────┘
                                │
                                ▼
                    ┌───────────────────────┐
                    │ 显示结果（文本+表格）    │
                    └───────────────────────┘
```

## 四、核心瓶颈分析

### 🟥 瓶颈 1：估值数据每只实时网络请求

- **位置**：每个评分器都调用 `StockFeatureProcessor.calculate_pe_pb()` → `akshare.stock_value_em()`
- **表现**：每次评分都从东方财富网实时拉取 PE/PB
- **影响**：全市场 5000 只 × ~0.5s = ~2500s
- **解决方案**：需要预缓存到 `valuation` 表（已有表但未被评分器使用）

### 🟥 瓶颈 2：财务数据缺失自动触发下载

- **位置**：`StatementDownload.get_financial_indicator_df()`
- **表现**：无缓存时自动调用 `download_financial_indicator(code)` 逐只下载
- **影响**：每只额外网络请求 ~1-3s

### 🟥 瓶颈 3：K 线缺失自动多源补拉

- **位置**：`Stock.get_daily_kline()`
- **表现**：无 K 线数据时尝试 4 个数据源（东方财富 → Tushare → 网易 → 腾讯）
- **影响**：XuXiang 评分器触发此流程

### 🟥 瓶颈 4：全局 sleep(0.1)

- **位置**：`market_scanner.py` 每只评分后
- **影响**：5000 × 0.1s = 500s

### 🟥 瓶颈 5：评分器每次重新创建

- **位置**：`market_scanner.py` 每只股票创建新 scorer 实例
- **影响**：StockFeatureProcessor 和数据库 Session 反复创建销毁

### 🟥 瓶颈 6：数据库逐只查询

- **位置**：5 年财务数据 = 3 张表 × 5 行查 5000 次 = 15000 次数据库查询
- **影响**：大量不必要的数据库 I/O

## 五、当前优势与局限

### 优势
1. ✅ **纯 Python**，开发调试方便
2. ✅ **本地数据库**，离线可用部分功能
3. ✅ **多种评分体系**，覆盖价值/趋势/排雷
4. ✅ **全市场扫描**，能找出 Top 标的
5. ✅ **AI 点评**，DeepSeek 大模型分析

### 局限
1. ❌ **仅限 Windows 桌面**，无法移动使用
2. ❌ **全市场扫描极慢**（5~30 分钟）
3. ❌ **Tkinter UI 老旧**，交互体验差
4. ❌ **依赖 akshare**，数据源变更需更新
5. ❌ **单机使用**，无法多人共享
6. ❌ **数据同步手动触发**，没有自动化定时
